# CAN 回读协议配置（故障验证）说明

故障码测试的**回读信号**不再写死在代码里，与 485 协议一样可在程序中编辑。

## 入口

报警测试 → 故障码测试 → 按钮 **「回读协议配置」**

配置文件：

`bms_alarm_test/config/can_readback_config.json`

## 可配置内容

| 区块 | 含义 |
|------|------|
| **信号表** | 配置键、信号名、报文名、CAN ID、扩展帧、字节序、起始位、长度、系数、偏移、通道角色 |
| **注入报文设置** | 故障注入/清除用的 CAN ID、扩展帧、地址/故障码/标志字节位置 |
| **角色绑定** | `inner_sys_fail_sta` / `inner_err_tab` / `outer_sys_fail_sta` / `outer_warning` → 信号表中的键 |
| **monitored_ids** | 对内/相关需监控的 CAN ID 列表（可增） |

## 典型用法

### 信号只改了 ID / 起始位 / 精度

1. 打开「回读协议配置」  
2. 直接改对应行的 CAN ID / 起始位 / 长度 / 系数 / 偏移  
3. **保存** → 再跑故障测试  

### 新增信号 / 换了 DBC

1. 「从 DBC 导入…」选择 DBC，选对内或对外  
2. 表中会填入该 DBC 里信号的 ID、起始位、长度、系数、偏移  
3. 检查后保存；必要时在「角色绑定」里指向新键  

### 参考「自制 CAN 接收文件」

表中每一行就是一条「接收定义」：`CAN ID + 位定义 + 系数/偏移`。  
可当轻量版接收文件用；不依赖 DBC 也能按位回读。

## 验证器如何工作

1. **优先**用 DBC 按信号名解码（若已加载对内/对外 DBC）  
2. 读不到时，按本配置的 **CAN ID + 起始位/长度/系数/偏移** 从最近原始帧解码  
3. 注入/清故障的报文 ID 也读本配置的 `inject.can_id`  

## 位定义约定

- **大端 Motorola(@0)**：`start_bit` 为 DBC 锯齿 MSB 位号（与 DBC/Vector 一致）  
- **小端 Intel(@1)**：`start_bit` 为 LSB 位号  
- 物理值 = 原始值 × 系数 + 偏移  

## 后续协议扩展

同类「读协议」功能建议都：

- 落到独立 JSON（可在界面改）  
- 提供 DBC/Excel 导入  
- 代码只保留「按配置解码」路径  

避免再把 CAN ID、位定义写死在 `.py` 里。
