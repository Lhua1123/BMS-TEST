# 界面样式踩坑

## 表格行内按钮被单元格内边距裁掉

**现象**：表格里的「设置 / 清除」按钮底部和右侧被切掉，圆角没了，像被吞掉一块；工具栏上的按钮（全选、反选等）却是完整的。

**原因**：`QTableWidget::item` 的 `padding` 不只作用于文字，也会压缩**单元格控件（cellWidget）**的可用区域。行内按钮外面那层居中容器被压扁后，会把超出部分裁掉。

**尺寸账**（行高 38、按钮列宽 84、按钮固定 72×32）：

| item padding | 控件可用区域 | 结果 |
|---|---|---|
| `6px 8px` | 67×25 | 按钮被裁右 5px、下 7px |
| `0px` | 83×37 | 按钮居中在 (13,2)，四周留白正常 |

**处理**：带行内按钮的表格用 `QTableWidget::item { padding: 0px; }`。
文字观感不变——名称列走 `LeftAlignDelegate`（自带 10px 缩进，不吃 QSS padding），其余列是居中对齐，垂直内边距对单行居中文字无影响。

**配套约束**：行高 38 / 按钮列宽 ≥84 / 按钮 72×32 是一套数。改任意一个要重算：
按钮宽 ≤ 列宽 − 2×水平内边距，按钮高 ≤ 行高 − 2×垂直内边距。
按钮直接塞进单元格（不加容器）也不行——Qt 会把控件钉在内容区左上角，不居中。

**已修**：阈值测试 PID 列表、故障码测试故障列表（两处写法相同）。
**未动**：`param_table` / `detail_table` 等纯文字表仍用 `padding: 6px 8px`，无此问题。

# 操作按钮行约定

**基准**：阈值测试页「阈值测试控制」那排按钮——按文字自适应宽度、间距 8、不锁死尺寸。故障码测试「测试控制」已对齐同一套（开始 / 停止 / 单步测试 / 配置验证）。

**不要用固定宽高方块**（曾用 `FAULT_CTRL_BTN_W/H = 132×34`）：四个大按钮排出来占 552px，被嫌不紧凑，已废除常量。自适应后整行约 260px。

**按钮文案是用户指定的**（两页都是：开始、停止、单步测试；故障页多一个配置验证），报告文案里会引用按钮名，改按钮文字要同步改报告里的引号串，否则报告读起来对不上界面。

**单步按钮的宽度权衡**：单步进行中文字会变成「单步测试 (n/m)」，按钮变宽、右边的按钮跟着挪一点。
**已决定接受这种挪动**，不要为「不跳动」去预留宽度——实测预留后单步按钮常年 122px（自然宽度只有 70px），胖得比跳动更难看。用户明确要「紧凑」。

**字号 12px / padding 3px 10px 下的实测宽度**：开始、停止 45~47px；单步测试 70~72px；配置验证 70px；带两位数计数约 122px。

# 两测试页统一约定（阈值页为准）

用户明确表态：**阈值测试页是设计基准**，故障码测试页要往它靠。

**按钮配色**（已两页一致）：开始/常规操作=蓝，停止=红，单步测试=橙黄，配置验证=蓝。
此前故障页把停止做成橙、单步做成蓝，已纠正。

**测试详情区结构**：外层一个「测试详情」分组框，里面直接放日志框 + 结果表格，**不要再套「实时日志」「验证详情」子分组框**（故障页原来是套的，会多出一层边框和标题，看起来跟阈值页不像）。日志用占位文字「实时日志」标示。

## 上下两块贴死：QSplitter 默认 handle 只有 2px

**现象**：日志框和结果表格上下紧贴，像粘在一起，中间只有一条细线。

**原因**：全局样式把 `QSplitter::handle:vertical` 定成了 `height: 2px`。分割器子控件之间只有这 2px，等于没缝。

**处理**：这类「上下两块要留缝」的分割器，本地设 `setHandleWidth(8)` 并把手柄设成透明。
别去改全局的 2px——监控页那些表格/寄存器分割线靠它做拖拽分隔，改了会一起变样。
